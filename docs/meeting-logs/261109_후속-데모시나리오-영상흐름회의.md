## 결정

- **공통 작업 기반 = Counter GitHub repo.** 팀원을 모두 초대하고, 회의록도 마크다운으로 여기에 올린다 (최수민). repo 링크는 디스코드에 새로 판 채널에 공유함 — 채널 이름은 전사상 "ICUIC"로 들려 미검증
- **데모 시나리오를 먼저 고정한다** (최수민). 영상 만들 때도, 제품 경험 설계에도 유리. 최수민은 **시스템 입장의 데모(요청이 어떻게 오고 응답을 어떻게 주는가)**를 만들고, 그 사례를 영상에서 어떻게 소개할지는 영상팀 몫
- **시나리오 3개, 국적·에이전트를 바꿔 보여 준다** — 아래 §데모 파트 영상 구성
- **최수민은 이 시나리오의 성능 측정(소요 시간 등)이 가능하도록 만든다**
- **영상 흐름(초안)**: 인트로 ~10초(시대 배경) → **문제 제기(problem statement)** → 솔루션 = 시스템 데모(~30초) → 클로징

  - 데모는 영상 큰 줄기 안의 한 부분일 뿐 — 데모가 주제가 되면 흐려진다
  - 이렇게 하면 40초 정도로 짧을 수 있음 → 늘린다면 뒤에 BM·시장 진입 전략. **일단 영상을 뽑고 판단**
- **기각: "비행기 타기 전에 맡기고 착륙하면 끝나 있다" 컨셉** — 일정 파악·대행은 Pickle 같은 개인 에이전트가 하는 일이라 Counter가 강조되지 않음 → 예약 시스템(가게 쪽) 중심으로 간다

## 데모 파트 영상 구성 (09:30~16:40 논의)

> 이 구간은 클로바노트 전사가 많이 깨져 있어 whisper large-v3로 다시 전사해 대조했다(숙소 에이전트 "낙지"→**Dots**, 이름 후보 "젠텍"→Gentact 등).

### 1) 기준 흐름 — 피부과 · Muse · 영어 (최수민)

영상에서 전체 흐름을 다 보여 줄 필요는 없다. 최수민이 시스템을 이 흐름대로 만들고, 영상팀이 어느 장면을 쓸지 고른다.

1. 사용자가 Muse(ChatGPT 등)에게 요청: **"Find skin care aesthetic in Korea"**
2. Muse가 검색 → **Google Maps 탐색** → 연락처를 찾다가 **Counter(에이전트용 연락 창구) 발견** → "컨택하겠습니다"
3. **에이전트끼리 대화**(에이전트 네트워킹) — Muse ↔ Counter
4. Counter가 **원장에게 신규 예약 승인 여부**를 묻는다 → **원장이 승인**
5. Counter가 Muse에게 예약 완료를 알린다 → **Muse가 사용자에게 예약 완료를 알린다**

- 알림 채널: Muse 쪽에 webhook 같은 수신 엔드포인트가 없어 Counter가 먼저 연락할 수 없다 → 요청 접수 때 Muse에게 연락처를 물어 **이메일 주소**를 받고, 승인되면 이메일로 알린다("메일을 보내도 Muse가 다 캐치하니 괜찮다"). 나중엔 에이전트들이 자체 수신 창구를 열 수도 있지만, 공개 창구는 프롬프트 인젝션·토큰을 태우는 DoS 공격에 노출돼 쉽게 못 열 것 — **영상 주제는 아님**

### 2) 시나리오 3개 × 국적 × 에이전트 (팀원 제안 → 합의)

| 업종 | 개인 에이전트 | 언어 |
|---|---|---|
| 피부과 예약 | Muse | 영어 |
| 식당 예약 | Pickle | 중국어 |
| 숙소 예약 | Dots | 베트남어 |

"3개 정도면 충분하다."

### 3) 연출 (최수민 + 팀원)

- **한 번은 흐름을 제대로 보여 주고, 컷 전환마다 사용자·언어·에이전트가 바뀐다.** 처음엔 Muse로 쭉 가다가, 컷이 바뀌면 베트남어를 쓰는 사용자이고 에이전트도 다른 것(최수민 예시로는 Grok)으로 바뀌어 있다 → 메시지: **"우리 것 하나면 전 세계 모든 AI 에이전트, 모든 국적을 커버한다"**
- **예약 완료 알림 장면: 알림 4개가 탁탁탁탁 연달아 뜨고, 사용자들이 웃으며 보는 컷.** ("맛있는데요")
- 레퍼런스(팀원): 중국어·일본어·프랑스어 등 여러 언어 옵션의 에이전트들이 한 번에 일을 끝내는 영상 → "그건 따라 하자"
- 최수민은 이 시나리오들의 **성능(소요 시간) 측정**이 가능하도록 만든다

### 4) 영상 안에서 데모의 위치

- 인트로 ~10초(시대 배경) → **문제 제기** → (선택) 우리 특징 짧은 소개 → **데모 = 솔루션 ~30초** → 클로징
- 데모는 "시스템 데모일 뿐" — 영상 큰 줄기 안에 들어가는 한 부분이다. 데모가 주제가 되면 흐려진다
- 문제를 먼저 보여 줘야 "얘네가 이걸 풀려고 만들었구나"가 이해된다(팀원 제안 채택). 문제 예: 바쁜 식당에 AI 전화가 너무 많이 와서 사장님이 짜증 남(AI slop)
- 이렇게 하면 40초 정도로 짧을 수 있음 → 늘린다면 뒤에 BM·시장 진입 전략. 기승전결이 팍팍 가야 한다. **일단 영상을 뽑고 판단**

### 5) 기각된 데모 컨셉

- **"비행기 타기 전에 맡기면 착륙할 때 끝나 있다"** (팀원): 미국인이 비행기 타기 전 에이전트에게 예약을 부탁 → 비행 중 에이전트 작업을 병렬로 보여 주고 → 착륙하면 완료. 에이전트가 보딩 패스·도착 시각·여행 일정까지 파악 → "그건 Pickle이 하는 일" → Counter가 강조되지 않음 → **예약 시스템(가게 쪽) 중심으로 간다**
- 참고로 나온 영상: 맥북과 폰의 에이전트 둘이 전화로 서로 에이전트임을 확인한 뒤 빠른 대화로 전환하는 영상

## 논의만 하고 정하지 않은 것

- **이름**: "Counter" 도메인이 비싸고(전사상 try-counter 등 언급), 구글에서 "counter"로 검색 걸릴 자신이 없다. 데모 흐름을 정리하다 "에이전트 컨택(Agent Contact) 발견"이라는 말이 나오자 "Contact가 더 잘 맞는다" → **"Gentact"(Agent Contact에서 A를 뺀 것)**가 네이밍 후보로 나옴. 확정 없음
- 챌린지 4번(AI Consumer Products for 1B People) 연결 논리: AI 회사들이 에이전트를 보급하려 경쟁 중 → 그들이 깔아 주는 에이전트가 곧 우리 유저가 된다
- Pickle 관점: Pickle도 전화를 걸었다가 사람들에게 혼나는 피드백 때문에 점점 소극적으로 변하는 중 → Counter로 오면 혼날 일이 없으니 Pickle 입장에서도 반길 것 (심사위원 Pickle CEO 겨냥 포인트)
- 레퍼런스: 공식 홈페이지의 90초 에이전트 소개 영상(어느 회사인지 전사 불명확)을 참고해 한 명이 영상 제작 · 에이전트 두 대(맥북·폰)가 서로 에이전트임을 확인하고 빠르게 대화로 전환하는 영상 · 한 팀원은 모션그래픽 소재를 갖고 있음
