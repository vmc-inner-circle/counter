# 261109 해커톤 현장 R&R·제품 스펙 회의 (10:05~10:25경)

전사 원문: `261109_현장-RnR-스펙회의_transcript.md` (화자 구분 없음 — 발언자는 맥락으로 추정)

## 결정

- **제품 빌드 = 최수민 1명.** 여러 명이 빌드하면 오히려 번거롭다. "UI·UX에 자신 있는 사람이 빌드해야 한다"는 의견에 따라 최수민이 맡음
- **영상 = 나머지 3명(황준식·이성렬·조순형).** 데모가 나온 뒤 영상을 만들면 늦으니, 데모 부분은 **플레이스홀더**로 비워 두고 영상을 먼저 만든 뒤 데모가 완성되면 채운다
- 영상 진행: 3명이 각자 대본 → **각자 영상 초안까지 뽑고**(AI 활용) → **영상으로 크로스 검토**(대본은 텍스트라 평가가 어려움) → 베이스 하나를 투표로 고르고 나머지 둘에서 좋은 부분을 가져와 합친다. 최수민 초안 대본(지하철에서 쓴 것)은 출발점으로 써도 되고 안 써도 됨
- 영상 다듬기에 시간을 최대한 쓴다 — "초안은 30분~2시간이면 나오지만 다듬는 데 대부분의 시간을 써야 한다"
- **싱크는 1시간마다**(최수민 추가 결정 — 11:30 · 12:30 · 13:30 · 14:30): 그때까지 나온 영상 결과물과 제품으로 맞춰 본다. 영상 만들다 제품에 필요한 게 생기면 그때그때 소통
- 소통 채널: **카톡** (디스코드는 보안 유출 우려로 제외. 이너서클 챌린저스 채널 안은 철회)
- 주제는 하나로: 세컨브레인·개인화를 섞자는 제안은 기각 — "90초에 주제 두 개는 집중력이 흩어진다"
- (산출물 목록에서 하나를 "그렇게 안 중요하다"며 뺐다 — 무엇인지 전사로는 확인 불가)

## 제품 스펙 (최수민 정리, 빌드 기준)

1. **에이전트 접속 창구 = 가게별 고유 URL.** 가게가 이 URL을 홈페이지·구글맵 등에 연락처처럼 등록 → Muse 같은 에이전트가 발견하면 가게에 직접 연락. 구체 통신 방식은 빌드 담당이 확정
2. **사장님(관리자)용 화면** — 대시보드는 당연해서 데모에서 "와우"가 안 나오니 핵심 장면은 따로:
   - **비가역 요청 승인 화면**: "이 예약 슬롯 잡아도 될까요?" (모바일 목업)
   - **모르는 지식 질문 → 사람에게 추가 설명 요청 → "앞으로 기억할까요?"**
   - 설정 페이지 1~2면
   - 영상에는 승인 절차만 넣어도 됨. 기능은 지원되는 게 맞다
3. **팀원 아이디어 (채택 방향)**: 기존 예약 페이지가 못 주는 **세부 정보** — 휠체어 이용 가능 여부 같은 접근성 정보, 공휴일(광복절 등) 예약 방침 — 를 에이전트가 물으면 바로 답한다. 없던 지식이면 사람에게 묻고 기억한다 → 데모 시나리오로 구성
4. **사람이 브라우저로 URL을 열면 채팅 GUI를 보여 준다** (사실상 챗봇 효과) — 기능 아이디어로는 좋지만 영상 주제가 흐려지니 **영상에는 넣지 않는 쪽**
5. **실측**: Pickle로 최수민에게 전화를 걸게 하고 최수민이 식당 주인 역할로 예약 과정을 밟아 소요 시간을 잰다 → 같은 일을 Counter로 해서 비교 → "압도적으로 빠르다"를 영상에 넣는다. 로컬로 띄우고 Claude Code를 에이전트로 붙여 요청해 본다

## 영상 원칙 (최수민)

- 쇼츠 논리: **3초 안에 가치, 10초 안에 설득.** 다만 심사위원은 피드를 내리는 사람이 아니라 볼 준비가 된 사람이라 약간 여유는 있음 — 그래도 10초 안에
- "여러분, 요즘 AI가 정말 많이 나오고 있죠"로 시작하면 실패
- 템포가 빨라야 한다. ElevenLabs 같은 음성은 배속, 컷도 빠르게
- 문제 배경: 에이전트가 잠재 고객으로 쏟아지는데 그들을 위한 제품이 없다 → 실제 세계 비즈니스를 그들에게 연결한다
- 시나리오: 외국인 관광객 · 접근성 같은 세부 정보 · "인간용 웹페이지와 다른 **에이전트 네이티브 컨택 포인트**"
- 앞부분 문제 제기를 "스타워즈 오프닝 자막"처럼 띄우는 아이디어도 나옴 — 한다면 2초 안에 올라가야
