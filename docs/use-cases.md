# Counter 유스케이스

> **확정** (2026-11-09 최수민) — 다음 싱크에서 공유한다.

**Counter가 해야 하는 일을 시스템 쪽에서 본 기준이다.** 빌드, 데모 녹화, 영상 대본은 여기 번호(`UC-1`)와 시나리오 이름(`피부과`)으로 부른다.

- 바꾸고 싶으면 1시간 싱크에서 말하고, 정해지면 이 문서를 먼저 고친다. 싱크 사이에는 고치지 않는다(오타는 예외).
- `미정`은 아직 팀이 정하지 않은 것이다. 추측해서 채우지 말고 싱크에서 정한다.
- 실측(전화 vs Counter)은 유스케이스가 아니라 이 유스케이스들을 재는 실험이다 → [measurement.md](measurement.md)
- 근거: [현장 R&R·스펙 회의](meeting-logs/261109_현장-RnR-스펙회의.md) · [데모 시나리오·영상 흐름 회의](meeting-logs/261109_후속-데모시나리오-영상흐름회의.md)

## 등장하는 쪽

| 이름 | 누구 | 무엇을 하나 |
|---|---|---|
| 개인 에이전트 | Muse · Pickle · Dots 등 | 사용자 대신 가게를 찾아 Counter에 문의하고 예약한다 |
| Counter | 가게마다 하나씩 있는 에이전트용 창구(URL) | 가게가 알려 준 정보로 답하고, 되돌릴 수 없는 일은 직원에게 승인받는다 |
| 사장님·직원 | 가게 사람 | 폰(`/admin`)으로 승인하고, 모르는 질문에 한 번 답한다 |

사용자(관광객)는 개인 에이전트와만 말한다. Counter와 직접 만나지 않는다.

## 유스케이스

| ID | 이름 | 사람 개입 | 구현 |
|---|---|---|---|
| UC-1 | 등록된 정보 문의 → 바로 답 | 없음 | 동작함 |
| UC-2 | 모르는 질문 → 직원이 한 번 답함 → 기억 | 첫 번째만 | 동작함 |
| UC-3 | 예약 요청 → 슬롯 잡아 둠 → 직원 승인 → 확정 | 탭 한 번 | 동작함 |
| UC-4 | 사장님이 가게 정보·기억을 관리 | 사장님이 직접 | 동작함 (일부) |
| UC-5 | 사람이 브라우저로 같은 URL을 열면 채팅 화면 | 없음 | 동작함 — **영상에는 넣지 않음** |

### UC-1 등록된 정보 문의 → 바로 답

1. 에이전트가 가게의 Counter URL(`/s/<가게>`)을 연다. 영업시간, 시술·메뉴, 가격, 접근성, 빈 슬롯, 기억한 답이 에이전트가 읽기 좋은 마크다운으로 나온다
   - 에이전트가 찾는 경로: 가게가 Google Maps·홈페이지 연락처에 올린 URL, `/.well-known/agent-card.json`, `/llms.txt`
   - Google Maps·홈페이지에 올리는 부분은 **미구현**이다. 영상 연출로만 나온다
2. 에이전트가 묻는다 (예: "휠체어로 들어갈 수 있나요?")
3. 가게가 등록한 정보에 있으면 Counter가 **직원을 부르지 않고 바로 답한다**

**성공 조건:** 일반 예약 페이지에는 없는 세부 정보(접근성, 공휴일 방침 등)를 사람 개입 없이 답한다.

### UC-2 모르는 질문 → 직원이 한 번 답함 → 기억

1. 에이전트가 등록된 정보에 없는 것을 묻는다 (예: "여성 의사가 있나요?")
2. Counter는 답을 지어내지 않고 **직원 폰에 질문을 띄운다**. 에이전트에게는 "확인 중"이라고 알린다
3. 직원이 답하고 **"기억할까요?"를 켠 채로** 보낸다
4. Counter가 그 답을 에이전트에게 전한다
5. **다른 에이전트**가 같은 질문을 하면 UC-1처럼 바로 답한다

**성공 조건:** 같은 질문으로 직원을 두 번 부르지 않는다. 비슷하지만 다른 질문("일본어 하는 직원" vs "중국어 하는 직원")에 기억한 답을 잘못 쓰지 않는다.

**같은 질문 판단(현재 구현):** 두 질문이 핵심 단어를 2개 이상 공유하고, 한쪽 질문의 핵심 단어가 80% 이상 다른 쪽에 들어 있으면 같은 질문으로 본다. 길게 물었던 질문을 짧게 다시 물어도, 그 반대여도 맞춘다. 애매하면 직원에게 다시 묻는다.

### UC-3 예약 요청 → 슬롯 잡아 둠 → 직원 승인 → 확정

1. 에이전트가 서비스, 날짜, 시간, 손님 정보를 보내 예약을 요청한다
2. Counter가 그 슬롯을 **잡아 두고** 직원 폰에 승인 요청을 띄운다. 빈 슬롯이 아니면 바로 거절하고 남은 슬롯을 알려 준다
3. 직원이 **승인**(또는 거절)한다
4. Counter가 에이전트에게 확정 번호를 준다

**성공 조건:** 직원은 탭 한 번만 하고, 승인 없이는 예약이 확정되지 않는다.

**완료 알림 방식(결정):** 에이전트가 `GET /tasks/:id?wait=60`으로 기다렸다가 받는다(롱폴링). 회의에서 나온 "이메일을 받아 두고 승인되면 메일로 알림"은 해커톤 이후로 미룬다 — 영상에서 차이가 보이지 않는다.

### UC-4 사장님이 가게 정보·기억을 관리

1. 사장님이 폰에서 `/admin`의 **Settings**를 열어 영업시간, 공휴일 방침, 접근성, 응대 언어, 결제, 의료 상담 안내를 고친다
2. 저장하면 에이전트가 보는 가게 문서(UC-1)에 **바로 반영된다**
3. **Memory**에서 Counter가 UC-2로 기억한 답을 확인하고, 틀렸거나 바뀐 답은 지운다

**성공 조건:** 가게가 고친 정보가 다음 문의부터 에이전트에게 나가고, 지운 기억으로는 더 답하지 않는다.

**미구현:** 시술·메뉴, 가격, 예약 슬롯은 화면에서 고칠 수 없다(seed 파일로만). 기억한 답은 지우기만 되고 고치기는 안 된다.

### UC-5 사람이 브라우저로 같은 URL을 열면 채팅 화면

1. 사람이 브라우저로 같은 Counter URL을 연다
2. Counter가 에이전트용 마크다운 대신 **가게 정보와 채팅 화면**을 보여 준다
3. 채팅으로 물으면 UC-1~2와 같은 방식으로 답한다

**성공 조건:** 같은 URL 하나로 에이전트와 사람을 다 받는다.

**영상에는 넣지 않는다**(R&R 회의 결정 — 주제가 흐려진다). 기능으로만 둔다.

## 범위 밖 (지금은 만들지 않는다)

- **예약 변경·취소** — 회의에서 다루지 않았고 데모·영상에 필요 없다
- **직원이 끝내 답하지 않는 경우** — 지금은 에이전트가 60초씩 다시 기다릴 뿐 시간 초과 처리가 없다. 데모에서는 생기지 않는다
- **에이전트 인증·프롬프트 인젝션 방어** — 회의에서 "영상 주제는 아님"으로 정했다
- **사장님 폰 잠금화면 푸시 알림** — 지금은 `/admin` 화면 안의 목록만 갱신된다. 영상에서 승인 요청이 뜨는 장면은 이 화면으로 찍는다
- **여러 에이전트 동시 문의** — 유스케이스가 아니라 시스템이 견뎌야 하는 성질이다. 필요하면 [실측 계획](measurement.md)에서 다룬다

## 데모 시나리오 — 같은 유스케이스, 다른 가게·에이전트·언어

시스템 동작은 세 시나리오 모두 같다. **바뀌는 것은 가게 데이터, 개인 에이전트, 사용자 언어뿐**이다. 영상 메시지는 "Counter 하나면 전 세계 모든 AI 에이전트와 모든 국적을 받는다"이다.

**공통 흐름**
1. 사용자가 자기 에이전트에게 모국어로 부탁한다 (피부과 예: "Find skin care aesthetic in Korea")
2. 에이전트가 검색과 Google Maps로 가게를 찾고, 연락처에서 **Counter URL을 발견**한다
3. UC-1로 세부 정보를 확인한다. 필요하면 UC-2를 거친다
4. UC-3으로 예약하고, 사장님이 폰에서 승인한다
5. 에이전트가 사용자에게 모국어로 예약 완료를 알린다

| 시나리오 | 개인 에이전트 | 사용자 언어 | 가게 데이터 | 영상 클립 |
|---|---|---|---|---|
| 피부과 | Muse | 영어 — 휠체어를 쓰는 영국인 관광객 Emma, 모르는 질문은 "여성 의사" | 있음 (`soi-derm`) | #1 |
| 식당 | Pickle | 중국어 | 없음 — 가게 이름·메뉴·슬롯 **미정** | #2 |
| 숙소 | Dots | 베트남어 | 없음 — 숙소 이름·객실·슬롯 **미정** | #3 |

- 언어는 사용자와 에이전트 사이의 일이다. Counter에는 에이전트가 영어로 묻고 Counter도 영어로 답한다(현재 구현). 따라서 식당·숙소에 새로 필요한 것은 가게 seed뿐이다
- 피부과 시나리오를 그대로 돌리는 명령은 루트 [README](../README.md#demo-scenario)에 있다
