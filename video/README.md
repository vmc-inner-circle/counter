**자기 폴더만 고친다**(`common/`은 싱크에서 정한 것만 올린다) — 그러면 서로 덮어쓰거나 충돌할 일이 없다. 남의 안에 의견은 카톡이나 그 사람 README 맨 아래 `## 코멘트`에 한 줄로.

## 올리는 법

- **영상·대본·자막·이미지 모두 자기 폴더에 자유롭게 올린다.**
- 브라우저 업로드는 파일당 25MB까지다. 더 크면 방법 2(git push)로 올린다 — 파일당 100MB까지 된다. 100MB를 넘으면 YouTube(일부 공개)·Loom·Drive에 올리고 링크를 자기 README에 적는다
- 방법 1 (브라우저): 자기 폴더 열기 → `Add file` → `Upload files` 또는 `README.md` 연필 아이콘 → `Commit changes` (main에 바로)
- 방법 2 (git/Claude Code): `git pull --rebase` → 자기 폴더 수정 → commit → push

- **프롬프트에 "최대한 빠르게 완성해라"를 넣는다.** 안 넣으면 HTML을 만든 뒤 브라우저에서 재생하며 화면을 녹화하는 식의 느린 방법을 고르기도 한다. 넣으면 눈에 띄게 빨라진다 ([상시녹음 1](../docs/meeting-logs/261109_상시녹음1-레포운영안내.md))

## 영상 메시지·연출 원칙

11:30 싱크에서 정했다 ([상시녹음 2](../docs/meeting-logs/261109_상시녹음2-영상시안리뷰-메시지.md)).

- **16:9 가로**로 만든다 (YouTube 제출용. 11:30엔 9:16이었으나 12:15~ [상시녹음 3](../docs/meeting-logs/261109_상시녹음3-영상방향-데모범위.md)에서 변경)
- 심사위원이 직접 접속해 보는 QR·링크는 넣지 않는다 — 한두 건으로는 Counter 정체성이 안 보이고 "AI 캐치테이블"로 오해된다 (상시녹음 3)
- **메인 플롯은 자동화**(에이전트 요청을 Counter가 대신 받아 처리), **글로벌(다국어)은 바로 이어지는 부가가치**
- **속도(전화보다 빠르다)는 넣지 않는다** — 주제가 늘어 구성이 부자연스러워진다
- **예약 확정처럼 기존 예약 플랫폼·에이전트가 이미 하는 일을 효용으로 내세우지 않는다.** 핵심은 흩어져 들어오는 에이전트 요청을 한 곳에서 정리해 사장님이 전화 슬롭에서 벗어나는 것
- **흐름이 보여야 한다: 사용자 → 개인 에이전트(Pickle 등) → Counter → 사장님.** 대부분 Counter에서 끝나고 일부만 사장님에게 간다
- Counter는 채팅 UI가 아니다. 기술 구현(링크 등)은 거의 안 보여도 되고, 로고 + "뒤에 사장님이 있고 Counter가 앞에서 막아 준다"로 표현한다
- **한 컷에 시선은 한 곳** — 한 컷이 2~3초다. 문구도 두 호흡으로 나눠 띄운다
- **스타일은 새로 창작하지 말고 레퍼런스 영상을 찾아 클론한다** — 그냥 만들라고 하면 슬롭이 나온다
