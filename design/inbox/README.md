# 사장님 화면(/admin) — UI 요구사항과 시안

11/09 최수민 정리. 기준은 [유스케이스](../../docs/use-cases.md) UC-1~3이다. 시안 데이터는 실제 서버에 요청을 보내 만든 응답 5건이다(손님 이름, 질문, 답, 확정 번호, 소요 초). 에이전트↔Counter 대화 장면은 영상팀이 모션그래픽으로 만든다. 이 문서의 범위가 아니다.

## 누가, 언제 보나

- **원장·직원**이 진료나 응대 중에 폰 알림을 보고 연다. 하는 일은 둘뿐이다: **예약 승인**(UC-3), **모르는 질문에 답하기**(UC-2)
- 남는 시간에 **문의 내역**을 본다. 에이전트가 무엇을 물었는지, 누가 답했는지 확인하는 용도다

## 요구사항

| ID | 요구사항 | 근거 |
|---|---|---|
| R1 | 열자마자 "내가 할 일"만 위에 보인다. 처리된 건은 아래나 다른 탭에 둔다 | UC-3 성공 조건 "탭 한 번" |
| R2 | 승인 카드: **일시가 1등 정보**다. 그 아래 시술·가격, 손님 이름·국적·메모(휠체어 등), 어느 에이전트인지, "승인 전엔 예약 안 됨"을 둔다. 버튼은 Decline / Approve 두 개 | UC-3 |
| R3 | 모르는 질문: 질문 원문, 답 입력, **"Remember for next time" 기본 켜짐**, 보내는 대상 에이전트 이름을 보여 준다 | UC-2 |
| R4 | 문의 내역: 손님 · 에이전트 · 질문이나 예약 · **누가 답했나**(가게 정보 / 기억 / 직원) · 걸린 시간. 손님 단위로 묶는다 | 11/09 최수민 요청 (채널톡 참고) |
| R5 | Memory · Store info 탭은 지금 그대로 둔다 | 영상에 안 나옴 |
| R6 | 상단 통계 3칸(agent requests / need you / answered)은 뺀다 — 볼 사람·시점이 없다 | 마피아MCP `kff28d305eb` |
| R7 | 문의 1건마다 테두리 색 카드를 씌우지 않는다. 같은 위계는 한 바탕에 나열하고, 굵은 글씨는 1등 정보에만 쓴다 | 마피아MCP `kca43f612e9` |

### 화면을 위해 서버가 바꿔야 할 것

- **UC-1 기록 없음**: 에이전트가 `.md`를 읽고 스스로 답하므로 Counter에는 질문이 남지 않는다. 읽은 사실을 `{type:'visit', agent}`로 남기면 내역에 "Muse read your store info" 한 줄이 생긴다. 무엇을 물었는지는 알 수 없다
- **질문의 손님 국적 없음**: `/book`은 `patient.nationality`를 받지만 `/ask`는 받지 않는다. 그래서 시안에서 Wang Fang·Haruto Sato는 국기가 없다. `/ask`에 `guest` 필드를 더할지는 미정
- **추천 답 칩**: Counter에는 LLM이 없다. 고정 칩(Yes / No / Please ask at the desk) 이상은 만들지 않는다. 시안 A의 문장형 추천 답은 예시다
- (버그) 승인 응답 문구에 "numbing cream"이 모든 시술에 붙는다. Laser Toning에도 붙는다

| 막히는 점 | 사장님이 "채팅으로 답해야 하나" 오해할 수 있다. 에이전트 대화를 모션그래픽으로 빼기로 한 것과 겹친다 | 손님 단위 묶음은 내역 탭에만 약하게 있다 | 손님이 많아지면 목록이 길어진다. 질문만 한 손님(Haruto)은 단계가 어색하다 |
